## What happened, in order

**1. Scoped the problem.** "Computer closed" turned out to be four different failure modes
(terminal closes / idle sleep / lid close / shutdown), each needing a different mechanism. Written
up in [`PROBLEM.md`](../PROBLEM.md). This framing is what stopped the work being a single
`caffeinate` call.

**2. Built the local lane.** `scripts/longrun.sh` with `start`/`ls`/`attach`/`stop`/`keepalive`/
`cloud`/`doctor`, tmux for the session, `caffeinate` for idle sleep, and a root watchdog for lid
close.

**3. Hit the detachment bug.** `caffeinate` launched with `nohup`+`disown` **died with its
launching shell** — a silent false green, since `keepalive` would have reported an assertion nobody
was holding. Fixed with `spawn_detached.py` (double fork + `os.setsid()`). The mechanism is
process-group signalling, not SIGHUP; [D-2](../decisions/DECISIONS.md).

**4. Tripped the integrity alarm.** Helpers were placed in `scripts/lib/`, a guarded surface. Moved
to `scripts/longrun/` rather than rebaselining the guard; [D-3](../decisions/DECISIONS.md).

**5. Proved the Cursor cloud lane.** Three throwaway scripts demonstrated dispatch, status polling
**from a separate process**, and follow-up steering against `platform-alpha`. The separate-process
result is what makes it a real lane rather than a way to block a terminal.

**6. Could not set the lid-close flag.** `pmset disablesleep` is root-only and `sudo` needed a
typed password at a real terminal — unavailable to an agent. Filed as **V-096** with the honest
status: the watchdog reads the flag back and reports `WILL SLEEP` rather than claiming a guarantee
it could not demonstrate.

**7. Solved it with GUI auth.** Added `gui_escalate` using `osascript`, which pops the native macOS
dialog and accepts Touch ID. Daniel authorised; the read-back printed
`lid close : SURVIVES (SleepDisabled=1)`, watchdog pid 45238. **V-096 closed.** This is the moment
the narrowed request was met.

**8. Found the suite disabling its own protection.** `verify_system.sh` starts and stops a
throwaway session daily, and `stop` called `keepalive off` — so **the daily verify run would have
silently killed Daniel's lid-close protection.** Fixed with keepalive ownership plus
`start --no-keepalive`; [D-4](../decisions/DECISIONS.md). Also fixed a false-positive in
`watchdog_running()` (it matched the `osascript` command line) and a suite crash caused by `exit`
inside an `eval`'d test.

**9. Spawned four subagents.** Three died on one transient DNS failure
(`ENOTFOUND agentn.global.api5.cursor.sh`) having written nothing. Full record in
[`agents/`](../agents/subagents-2026-07-29.md).

**10. The research agent changed the plan.** It produced
`PRs/longrun-remote/RESEARCH-FINDINGS.md` — 40KB, primary sources — which killed the Actions lane
on policy, exposed the Cursor rate limit, corrected the spawner mechanism, and surfaced a
first-party Claude cloud lane that had been missed entirely.

**11. Fixed a defect the research surfaced.** `/v0/repositories` allows ~1 request/user/minute, and
`doctor` called it every run. Because the refusal keys off an empty list, a 429 could render as "no
repositories connected" — the opposite diagnosis. Fixed with `cursor_repos.py`;
[D-5](../decisions/DECISIONS.md).

**12. Corrected the GCP claim.** An earlier reading said gcloud was unauthenticated; it was read
mid-initialisation. It **is** authenticated with 11 projects — but the only billing account is
**closed**, so GCP is unusable for a VM regardless. Filed as **V-101**.

**13. Got the Claude cloud lane wrong, then right.** Declared `claude --cloud` non-existent because
it was absent from `--help` — but the research doc had **already said** the flags are hidden. A
second probe was invalid because the bogus control also passed. `strings` on the binary settled it:
`teleport` 191 hits, `web-setup` 9, `CCR_FORCE_BUNDLE` 5. The lane is real and is probably the best
fit. [D-6](../decisions/DECISIONS.md); correction filed as **V-102**.

**14. Wrote this folder** so none of the above is rediscovered.

**15. The keepalive footgun fired again — after being "fixed".** At 19:57 the keepalive was torn
down by an explicit release, killing lid-close protection Daniel had authorised by Touch ID. Step 8
had supposedly closed this. It had not: section 14's cleanup **deletes the owner file**, and an
absent owner fell through to the release branch, so `stop` released a root watchdog it had never
started. With `caffeinate` gone the Mac idle-slept **under the running verify suite**, which took
**75 minutes** instead of 125 seconds. Diagnosed and fixed by the session-manager subagent — which
got the root cause right after I had guessed a different one. [D-4a](../decisions/DECISIONS.md).

**16. Session manager landed.** `longrun cloud ls/status/logs/send/stop`, taking the suite from 76
to **83 checks, 0 failed** — including `stop never releases a keepalive it does not own`,
`429 reads UNKNOWN + stale cache dated`, and `follow poll floor >=15s`.

## Bugs found and fixed

| Bug | Why it mattered |
|---|---|
| `caffeinate` died with its launching shell | Silent false green on the whole power layer |
| `keepalive_on` called `die` on sudo decline | Aborted `start` after the tmux session already existed |
| Declining sudo leaked a `caffeinate` process | `keepalive_off` only released it if the watchdog was running |
| Helpers in `scripts/lib/` | Tripped the integrity alarm |
| `pipe-pane … 'cat >> log'` block-buffered | Log lagged the live pane; looked like lost output |
| `verify_system.sh` disabled operator keepalive | **The test suite would have slept the machine** |
| `watchdog_running()` matched `osascript` | Reported the watchdog running when only the dialog was pending |
| `exit` inside an `eval`'d test | Terminated the whole suite early |
| Uncached rate-limited repo read | A 429 could read as "no repos connected" — opposite diagnosis |
