**None of these is ever hand-edited.** A hand-edited ledger breaks `last` and `cs ls` in
ways that look like a CLI bug; a hand-edited heartbeat file is a forged claim about an agent
you are not; a hand-edited manifest dispatches the wrong branches. Use `cs rm` to remove a
ledger row, re-run `cs exodus` to rebuild a manifest, and leave heartbeats alone — they are
somebody else's testimony.

## `sessions.jsonl` — the dispatch ledger

Append-only JSON Lines, one object per dispatch:

`ts` (local ISO timestamp) · `id` (session ID) · `title` (the task string) · `repo` ·
`branch` · `mode` (`clone`, `bundle`, or `tracked` for a session started on the web or phone
and recorded after the fact) · `url` (the claude.ai/code link). `cs track` adds the
provenance fields: `lane`, `owns`, `from`, `brief`, `trigger_id`, `expect_branch`.

It exists because there is no CLI command that lists cloud sessions non-interactively.
`cs ls` reads it so the list survives a reboot, `last` resolves through it so you never
copy-paste a session ID, and `cs fleet` merges every other source **onto** it — a heartbeat
with no ledger row is still rendered, but labelled as having no dispatch record.

**It is a convenience index, not the authoritative list.** claude.ai/code is authoritative;
sessions started on the web or the phone do not appear here unless someone ran `cs track`.
`cs ls` says so in its own output.

**Tracked on purpose since 2026-08-14.** It was gitignored as ordinary runtime state until
measuring cloud sessions showed it is the *only* record of a dispatched session that
survives: a cloud session's own hook telemetry is written to the VM's disk and discarded
when the VM is reclaimed, and it deliberately does not commit that trace (per the now-archived
[`verified-facts.md`](../archive/foreign-repo-provenance-2026-08-18/verified-facts.md), written
against the other repo but describing a mechanism-level fact that still holds here). So the
dispatch-side row here, plus the branch or PR the session produces, *is* the record.

*Superseded 2026-08-17:* an earlier paragraph here said the ledger was ignored and
untracked. It is not — `git ls-files` lists it and `git check-ignore` exits 1. The stale
wording mattered: a porter reading it concludes a clone will not carry the rows, and a clone
does. See [`../playbooks/09-porting-to-another-repo.md`](../playbooks/09-porting-to-another-repo.md)
step 2 — truncate the ledger when porting.

## `exodus-manifest.json` — the departure plan

Written by `cs exodus` when it partitions a dirty working tree by the heartbeat board's
owns-claims: one unit per lane, each with its `claude/<lane>` branch and what belongs on it.
It is a **plan, not an action** — `cs exodus` dispatches nothing; `/cloud all` reads this
file and does the dispatching. Rebuild it by re-running `cs exodus`, never by editing it:
the branches it names have to exist, and a hand-edited unit sends an agent at work that was
never moved. `cs exodus --dry-run` prints the partition without writing anything.

## `fleet/` — the cloud heartbeat directory

The landing zone for what cloud agents say about themselves. One JSON file per session,
named for the session id. On the VM it is what gets **pushed**; on your laptop it is a read
**cache** of what was fetched. Same directory, two roles.

The path a beat takes, and why it is this shape: a VM's telemetry dies with the VM, and the
heartbeat board does not travel to a VM usefully (`V-021`), so **git push is the only
channel that survives a closed laptop**. The emitter writes the file, then pushes that one
file to `refs/heads/cloud-fleet/<session-id>` using plumbing, so telemetry never lands on
the lane's work branch and never enters a PR diff.

**These files are not tracked, deliberately.** The emitter drops a `.gitignore` here
covering `*.json`, `*.json.corrupt-*` and `.locks/` on its first beat, so a `git add -A` in
the agent's real work cannot sweep telemetry into its commit. The push path uses plumbing
and is unaffected by that ignore rule. What is durable is the **ref**, not the file.

To read the fleet on your laptop you fetch the refs and materialise them here — the loop is
in [`../playbooks/10-fleet.md`](../playbooks/10-fleet.md) §3, and it is required, not
optional: `cs fleet` reads files, not the `cloud-fleet/*` refs. A file that is not
materialised is an agent that reads as "never reported".

`cs fleet --prune` is the only thing that deletes from here, and only for a run that is
**over** with known provenance — the ledger marks it finished, or the agent's own last word
was `done` and a ledger row exists. Never `failed` (its last words are the reason you would
look), never blocked, waiting, working, starting, unknown, untrusted, stale-but-live, and
never a heartbeat with no ledger row. Refusals are printed with their reason.
`--prune --dry-run` shows the same decisions and removes nothing.

## Rules

- **Never hand-edit anything in this directory.**
- **Never put a credential here.** No API keys, tokens, GitHub PATs or connector secrets, in
  any form — including inside a task string that `cs start` records verbatim into `title`,
  or a `--detail` string an agent passes to the emitter, which is pushed to git. If a secret
  ever reaches the ledger, delete the file rather than editing around it; it is regenerable
  and losing it costs nothing but the local list. If one reaches a pushed heartbeat, treat
  it as leaked: the ref is on origin.
- **`sessions.jsonl` and `exodus-manifest.json` are committed.** They carry session IDs,
  task strings composed from repository state, lane names and branch names. Session IDs are
  addresses into a live account.
- **`fleet-ui.html` and `hook-errors.log` are neither tracked nor ignored** as of 2026-08-18
  (`git check-ignore` exits 1 for both), so they show up as untracked files. Do not commit
  them; the page is regenerable in one command and the log is local diagnostics.
- The whole directory is safe to delete except for the two tracked files. `cs` recreates it
  on the next dispatch; only local history and the heartbeat cache are lost, and the cache
  can be re-fetched from the refs.
